## 一、需求分析

### 1.1 业务背景

岗位是组织架构中的重要组成部分，用于配置用户所属职务。在企业管理系统中，岗位信息与用户信息密切关联，一个用户可以拥有多个岗位。

### 1.2 功能需求

| 需求点 | 描述 | 优先级 |
|--------|------|--------|
| 岗位列表 | 查询岗位列表，支持分页和筛选 | P0 |
| 岗位详情 | 根据岗位ID查询岗位详情 | P0 |
| 新增岗位 | 创建新的岗位信息 | P0 |
| 修改岗位 | 更新已有的岗位信息 | P0 |
| 删除岗位 | 删除指定的岗位 | P0 |

### 1.3 非功能需求

- 岗位编码必须唯一
- 岗位删除时需校验是否有用户关联
- 支持逻辑删除

## 二、技术方案

### 2.1 数据库设计

#### sys_post 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| post_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 岗位ID |
| post_code | VARCHAR(64) | NOT NULL, UNIQUE | 岗位编码 |
| post_name | VARCHAR(50) | NOT NULL | 岗位名称 |
| post_sort | INT | NOT NULL | 显示顺序 |
| status | CHAR(1) | DEFAULT '0' | 状态（0正常 1停用） |
| create_by | VARCHAR(64) | DEFAULT '' | 创建者 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_by | VARCHAR(64) | DEFAULT '' | 更新者 |
| update_time | DATETIME | NULL ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| remark | VARCHAR(500) | NULL | 备注 |
| del_flag | CHAR(1) | DEFAULT '0' | 删除标志（0存在 2删除） |

#### sys_user_post 关联表（用户-岗位关联）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| user_id | BIGINT | PRIMARY KEY | 用户ID |
| post_id | BIGINT | PRIMARY KEY | 岗位ID |

### 2.2 接口设计

#### 2.2.1 岗位列表

```
GET /system/post/list
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | Integer | ❌ | 页码，默认 1 |
| pageSize | Integer | ❌ | 每页条数，默认 10 |
| postName | String | ❌ | 岗位名称，模糊匹配 |
| postCode | String | ❌ | 岗位编码，模糊匹配 |
| status | String | ❌ | 状态（0正常 1停用） |

**成功响应**：

```json
{
  "code": 200,
  "data": {
    "total": 10,
    "rows": [
      {
        "postId": 1,
        "postCode": "admin",
        "postName": "管理员",
        "postSort": 1,
        "status": "0",
        "remark": "管理员岗位",
        "createTime": "2026-07-17 10:00:00"
      }
    ]
  }
}
```

#### 2.2.2 岗位详情

```
GET /system/post/{postId}
```

**成功响应**：

```json
{
  "code": 200,
  "data": {
    "postId": 1,
    "postCode": "admin",
    "postName": "管理员",
    "postSort": 1,
    "status": "0",
    "remark": "管理员岗位",
    "createTime": "2026-07-17 10:00:00"
  }
}
```

#### 2.2.3 新增岗位

```
POST /system/post
```

**请求体**：

```json
{
  "postCode": "developer",
  "postName": "开发工程师",
  "postSort": 2,
  "status": "0",
  "remark": "开发岗位"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| postCode | String | ✅ | 2-64 字符，唯一 |
| postName | String | ✅ | 2-50 字符 |
| postSort | Integer | ✅ | 正整数 |
| status | String | ❌ | 0/1，默认 0 |
| remark | String | ❌ | 最大 500 字符 |

**成功响应**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

#### 2.2.4 修改岗位

```
PUT /system/post
```

**请求体**：

```json
{
  "postId": 1,
  "postCode": "admin",
  "postName": "高级管理员",
  "postSort": 1,
  "status": "0",
  "remark": "高级管理员岗位"
}
```

**成功响应**：同上

#### 2.2.5 删除岗位

```
DELETE /system/post/{postIds}
```

**路径参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| postIds | Long[] | 岗位ID，多选用逗号分隔 |

**成功响应**：同上

## 五、数据库脚本

```sql
-- 岗位表
DROP TABLE IF EXISTS sys_post;
CREATE TABLE sys_post (
    post_id     BIGINT NOT NULL AUTO_INCREMENT COMMENT '岗位ID',
    post_code   VARCHAR(64) NOT NULL UNIQUE COMMENT '岗位编码',
    post_name   VARCHAR(50) NOT NULL COMMENT '岗位名称',
    post_sort   INT NOT NULL COMMENT '显示顺序',
    status      CHAR(1) DEFAULT '0' COMMENT '状态（0正常 1停用）',
    create_by   VARCHAR(64) DEFAULT '' COMMENT '创建者',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_by   VARCHAR(64) DEFAULT '' COMMENT '更新者',
    update_time DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    remark      VARCHAR(500) DEFAULT NULL COMMENT '备注',
    del_flag    CHAR(1) DEFAULT '0' COMMENT '删除标志（0存在 2删除）',
    PRIMARY KEY (post_id)
) ENGINE=InnoDB AUTO_INCREMENT=100 COMMENT='岗位信息表';

-- 用户岗位关联表
DROP TABLE IF EXISTS sys_user_post;
CREATE TABLE sys_user_post (
    user_id BIGINT NOT NULL COMMENT '用户ID',
    post_id BIGINT NOT NULL COMMENT '岗位ID',
    PRIMARY KEY (user_id, post_id)
) ENGINE=InnoDB COMMENT='用户和岗位关联表';

-- 初始数据
INSERT INTO sys_post VALUES (1, 'admin', '管理员', 1, '0', 'admin', NOW(), '', NULL, '管理员岗位', '0');
INSERT INTO sys_post VALUES (2, 'developer', '开发工程师', 2, '0', 'admin', NOW(), '', NULL, '开发岗位', '0');
INSERT INTO sys_post VALUES (3, 'tester', '测试工程师', 3, '0', 'admin', NOW(), '', NULL, '测试岗位', '0');

-- 用户岗位关联
INSERT INTO sys_user_post VALUES (1, 1);
INSERT INTO sys_user_post VALUES (2, 2);
```

## 六、测试用例

| 测试场景 | 请求 | 预期结果 |
|---------|------|---------|
| 查询岗位列表 | `GET /system/post/list` | 返回分页数据 |
| 查询岗位详情 | `GET /system/post/1` | 返回岗位信息 |
| 新增岗位 | `POST /system/post` | 创建成功 |
| 新增重复编码 | `POST /system/post`，postCode重复 | 返回 400 错误 |
| 修改岗位 | `PUT /system/post` | 更新成功 |
| 删除岗位 | `DELETE /system/post/3` | 删除成功 |
| 删除有用户关联的岗位 | `DELETE /system/post/1` | 返回 400 错误 |
| 权限不足访问 | 无权限用户访问 | 返回 403 |
