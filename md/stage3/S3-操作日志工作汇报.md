# S3-操作日志工作汇报

> 生成日期：2026-08-06
> 状态：✅ 已完成

---

## 一、概述

操作日志模块通过 AOP 切面自动记录系统操作行为，支持审计追踪和问题排查。日志记录异步写入数据库，不影响业务性能。

---

## 二、接口清单

| 接口 | 方法 | 权限标识 | 说明 |
|------|------|---------|------|
| `/monitor/operlog/list` | GET | monitor:operlog:list | 分页查询操作日志列表 |
| `/monitor/operlog/{operId}` | GET | monitor:operlog:query | 查询操作日志详情 |
| `/monitor/operlog/{operIds}` | DELETE | monitor:operlog:remove | 删除操作日志 |
| `/monitor/operlog/clean` | DELETE | monitor:operlog:clean | 清空操作日志 |

---

## 三、关键实现

### 3.1 AOP 切面自动记录

- **自定义注解** `@OperLog`：标注在 Controller 方法上，声明操作模块、业务类型等
- **切面** `OperLogAspect`：通过 `@Around` 环绕通知自动记录操作日志
- **异步保存**：使用 `@Async` 异步写入数据库，不阻塞业务流程

### 3.2 日志记录内容

| 字段 | 说明 | 来源 |
|------|------|------|
| title | 操作模块 | @OperLog 注解 |
| businessType | 业务类型 | @OperLog 注解 |
| method | 方法名称 | 反射获取 |
| requestMethod | 请求方式 | HttpServletRequest |
| operName | 操作人员 | SecurityUtils |
| operIp | 主机地址 | HttpServletRequest |
| operParam | 请求参数 | 序列化方法参数 |
| jsonResult | 返回参数 | 序列化返回值 |
| status | 操作状态 | 0正常 1异常 |

### 3.3 物理删除

操作日志表无 `del_flag` 字段，删除时直接物理删除（`DELETE`），不使用逻辑删除。

---

## 四、数据库表

**sys_oper_log 表**：含 oper_id/title/business_type/method/request_method/operator_type/oper_name/dept_name/oper_url/oper_ip/oper_location/oper_param/json_result/status/error_msg/oper_time
