# S0-认证模块工作汇报

> 生成日期：2026-06-15
> 状态：✅ 已完成

---

## 一、概述

AuthController 提供四个认证接口：**注册、登录、获取当前用户信息、登出**。本文档逐一梳理每个接口的完整数据链路——从 HTTP 请求进入 Controller 开始，到数据库的每一张表、Redis 的每一个 Key、Spring Security 的上下文传递，最终返回给前端的 JSON 结构。

---

## 二、接口清单

| 接口 | 方法 | 权限 | 说明 |
|------|------|------|------|
| `/auth/login` | POST | 无 | 用户登录 |
| `/auth/register` | POST | 无 | 用户注册 |
| `/auth/info` | GET | 需认证 | 获取当前用户信息 |
| `/auth/logout` | POST | 需认证 | 用户登出 |

## 三、接口详细数据链路

### 3.1 用户注册 `POST /auth/register`

**请求数据**：

| 字段 | 来源 | 校验规则 |
|------|------|----------|
| `username` | 用户输入 | 2-30 字符，不为空 |
| `password` | 用户输入 | 6-20 字符，不为空 |
| `nickname` | 用户输入 | 不为空，最长 30 字符 |
| `email` | 用户输入（选填） | 合法邮箱格式，最长 50 字符 |
| `phonenumber` | 用户输入（选填） | 最长 11 字符 |

**数据链路**：

```
RegisterReq (JSON Body)
  │
  ▼
AuthController.register()
  │
  ▼
AuthServiceImpl.register()
  │
  ├─► SysUserServiceImpl.registerUser(RegisterReq)
  │     │
  │     ├─ MapStruct (AuthConvert) 做字段映射
  │     │   RegisterReq.username → SysUser.userName
  │     │   RegisterReq.nickname → SysUser.nickName
  │     │   RegisterReq的其他字段 → SysUser对应字段
  │     │
  │     ├─ 设置 status = "0"（正常状态）
  │     │
  │     ├─ prepareNewUser():
  │     │   ├─ 校验用户名唯一性:
  │     │   │   SysUserMapper.selectUserByUserName()
  │     │   │   └─ 已存在则抛出 BusinessException
  │     │   │
  │     │   └─ BCryptPasswordEncoder.encode(password) 加密密码
  │     │
  │     └─ SysUserMapper.insert() → sys_user 表
  │
  └─► SysUserRoleServiceImpl.insertUserRole()
        └─ 将新用户关联到「普通角色」(role_id=2)
```

---

### 3.2 用户登录 `POST /auth/login`

**请求数据**：

| 字段 | 来源 | 校验规则 |
|------|------|----------|
| `username` | 用户输入 | 不为空 |
| `password` | 用户输入 | 不为空 |

**数据链路**：

```
LoginReq (JSON Body)
  │
  ▼
AuthController.login()
  │
  ▼
LoginService.login()
  │
  ├─[步骤1]─► SysUserMapper.selectUserByUserName(username)
  │            └─ 查询 sys_user 表
  │            └─ 用户不存在则抛出 AuthenticationException
  │
  ├─[步骤2]─► BCryptPasswordEncoder.matches(password, user.password)
  │            └─ 密码不匹配则抛出 AuthenticationException
  │
  ├─[步骤3]─► 校验用户状态 status == "0"
  │            └─ 状态异常则抛出 AuthenticationException
  │
  ├─[步骤4]─► TokenService.createToken(user)
  │            │
  │            ├─ JwtTokenProvider.generateToken(user)
  │            │   └─ 生成 JWT Token，包含 userId、userName、roles
  │            │
  │            └─ Redis 存储 Token:
  │                 Key: login_tokens:{userId}
  │                 Value: {token}
  │                 Expire: 24小时
  │
  ├─[步骤5]─► 构建 LoginResp:
  │            ├─ userId, userName, nickName
  │            ├─ token, loginTime, expireTime
  │            ├─ ip, address
  │            ├─ permissions (从 Redis 或数据库获取)
  │            └─ roles
  │
  └─[步骤6]─► 更新登录信息:
               └─ SysUserMapper.updateLoginInfo(userId, ip, loginDate)
```

---

### 3.3 获取当前用户信息 `GET /auth/info`

**数据链路**：

```
GET /auth/info
        │
        ▼
JwtAuthenticationFilter (Spring Security)
        │
        ├─► 从请求头提取 Authorization: Bearer {token}
        │
        ├─► JwtTokenProvider.validateToken(token)
        │
        ├─► JwtTokenProvider.getUserId(token)
        │
        └─► SecurityContextHolder 存入 Authentication
                │
                ▼
AuthController.info()
        │
        ▼
LoginService.getLoginUser()
        │
        ├─► 从 SecurityContext 获取 userId
        │
        ├─► SysUserMapper.selectUserById(userId)
        │
        ├─► SysRoleService.getRoleKeys(userId) → 获取角色列表
        │
        └─► SysMenuService.getMenuPermissions(userId) → 获取权限列表
```

---

### 3.4 用户登出 `POST /auth/logout`

**数据链路**：

```
POST /auth/logout
        │
        ▼
AuthController.logout()
        │
        ▼
TokenService.logout()
        │
        ├─► 从请求头获取 Token
        │
        ├─► JwtTokenProvider.getUserId(token)
        │
        └─► Redis 删除 Key: login_tokens:{userId}
                └─ Token 立即失效
```

## 四、关键实现

### 4.1 JWT Token 结构

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
{
  "sub": "1",
  "username": "admin",
  "roles": ["admin"],
  "exp": 1718505600
}
```

### 4.2 Redis Key 设计

| Key | 说明 | 过期时间 |
|-----|------|---------|
| login_tokens:{userId} | 存储用户的有效 Token | 24小时 |

### 4.3 密码加密

使用 Spring Security 的 `BCryptPasswordEncoder`，每次加密结果不同，但可通过 `matches()` 验证。
