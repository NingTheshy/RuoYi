## 一、需求分析

### 1.1 业务背景

通知公告用于发布系统公告、通知等信息，用户登录后可以查看公告内容。公告支持置顶、过期等功能。

### 1.2 功能需求

| 需求点 | 描述 | 优先级 |
|--------|------|--------|
| 公告列表 | 查询公告列表，支持分页和筛选 | P0 |
| 公告详情 | 根据公告ID查询公告详情 | P0 |
| 新增公告 | 创建新的公告 | P0 |
| 修改公告 | 更新已有的公告 | P0 |
| 删除公告 | 删除指定的公告 | P0 |

### 1.3 非功能需求

- 公告支持置顶标记
- 公告支持过期时间设置
- 支持按发布时间排序

## 二、技术方案

### 2.1 数据库设计

#### sys_notice 表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| notice_id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 公告ID |
| notice_title | VARCHAR(50) | NOT NULL | 公告标题 |
| notice_type | CHAR(1) | DEFAULT '1' | 公告类型（1通知 2公告） |
| notice_content | TEXT | NULL | 公告内容 |
| status | CHAR(1) | DEFAULT '0' | 状态（0正常 1停用） |
| create_by | VARCHAR(64) | DEFAULT '' | 创建者 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_by | VARCHAR(64) | DEFAULT '' | 更新者 |
| update_time | DATETIME | NULL ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| remark | VARCHAR(500) | NULL | 备注 |

### 2.2 接口设计

#### 2.2.1 公告列表

```
GET /system/notice/list
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | Integer | ❌ | 页码，默认 1 |
| pageSize | Integer | ❌ | 每页条数，默认 10 |
| noticeTitle | String | ❌ | 公告标题，模糊匹配 |
| noticeType | String | ❌ | 公告类型（1通知 2公告） |
| status | String | ❌ | 状态（0正常 1停用） |

**成功响应**：

```json
{
  "code": 200,
  "data": {
    "total": 5,
    "rows": [
      {
        "noticeId": 1,
        "noticeTitle": "系统升级通知",
        "noticeType": "1",
        "noticeContent": "<p>系统将于今晚22:00进行升级维护...</p>",
        "status": "0",
        "createTime": "2026-07-17 10:00:00"
      }
    ]
  }
}
```

#### 2.2.2 公告详情

```
GET /system/notice/{noticeId}
```

**成功响应**：同上（单条记录）

#### 2.2.3 新增公告

```
POST /system/notice
```

**请求体**：

```json
{
  "noticeTitle": "新功能上线",
  "noticeType": "2",
  "noticeContent": "<p>系统新增字典管理功能...</p>",
  "status": "0",
  "remark": "新功能公告"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| noticeTitle | String | ✅ | 2-50 字符 |
| noticeType | String | ✅ | 1/2，默认 1 |
| noticeContent | String | ✅ | 公告内容 |
| status | String | ❌ | 0/1，默认 0 |
| remark | String | ❌ | 最大 500 字符 |

**成功响应**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

#### 2.2.4 修改公告

```
PUT /system/notice
```

**请求体**：

```json
{
  "noticeId": 1,
  "noticeTitle": "系统升级通知（更新）",
  "noticeType": "1",
  "noticeContent": "<p>系统升级时间调整为今晚23:00...</p>",
  "status": "0",
  "remark": "系统升级公告"
}
```

**成功响应**：同上

#### 2.2.5 删除公告

```
DELETE /system/notice/{noticeIds}
```

**成功响应**：同上

## 五、数据库脚本

```sql
-- 通知公告表
DROP TABLE IF EXISTS sys_notice;
CREATE TABLE sys_notice (
    notice_id      BIGINT NOT NULL AUTO_INCREMENT COMMENT '公告ID',
    notice_title   VARCHAR(50) NOT NULL COMMENT '公告标题',
    notice_type    CHAR(1) DEFAULT '1' COMMENT '公告类型（1通知 2公告）',
    notice_content TEXT DEFAULT NULL COMMENT '公告内容',
    status         CHAR(1) DEFAULT '0' COMMENT '状态（0正常 1停用）',
    create_by      VARCHAR(64) DEFAULT '' COMMENT '创建者',
    create_time    DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_by      VARCHAR(64) DEFAULT '' COMMENT '更新者',
    update_time    DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    remark         VARCHAR(500) DEFAULT NULL COMMENT '备注',
    PRIMARY KEY (notice_id)
) ENGINE=InnoDB AUTO_INCREMENT=100 COMMENT='通知公告表';

-- 初始数据
```
