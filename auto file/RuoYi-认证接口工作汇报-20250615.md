# RuoYi 认证模块（AuthController）工作汇报

> 生成日期：2026-06-15

***

## 一、概述

AuthController 提供四个认证接口：**注册、登录、获取当前用户信息、登出**。本文档逐一梳理每个接口的完整数据链路——从 HTTP 请求进入 Controller 开始，到数据库的每一张表、Redis 的每一个 Key、Spring Security 的上下文传递，最终返回给前端的 JSON 结构。

***

## 二、接口一：用户注册 `POST /auth/register`

### 2.1 请求数据

前端发送 JSON Body，包含五个字段：

| 字段            | 来源       | 校验规则            |
| ------------- | -------- | --------------- |
| `username`    | 用户输入     | 2-30 字符，不为空     |
| `password`    | 用户输入     | 6-20 字符，不为空     |
| `nickname`    | 用户输入     | 不为空，最长 30 字符    |
| `email`       | 用户输入（选填） | 合法邮箱格式，最长 50 字符 |
| `phonenumber` | 用户输入（选填） | 最长 11 字符        |

### 2.2 数据链路

```
RegisterReq (JSON Body)
  │
  ▼
AuthController.register()
  │  日志：[注册] 收到注册请求
  │
  ▼
AuthServiceImpl.register()
  │
  ├─[步骤1]─► SysUserServiceImpl.registerUser(RegisterReq)
  │            │
  │            ├─ MapStruct (AuthConvert) 做字段映射:
  │            │   RegisterReq.username  → SysUser.userName
  │            │   RegisterReq.nickname  → SysUser.nickName
  │            │   RegisterReq的其他字段 → SysUser对应字段
  │            │
  │            ├─ 设置 status = "0"（正常状态，枚举值 StatusFlag.NORMAL）
  │            │
  │            ├─ prepareNewUser():
  │            │   ├─ 校验用户名唯一性:
  │            │   │   SysUserMapper.selectUserByUserName()
  │            │   │   → SQL: SELECT * FROM sys_user WHERE user_name=? AND del_flag='0'
  │            │   │   如果已存在同名用户 → 抛异常 400
  │            │   │
  │            │   ├─ BCrypt 加密密码 → SysUser.password 存储的是哈希值，非明文
  │            │   │
  │            │   └─ 设置 delFlag = "0"（正常，非删除）
  │            │
  │            ├─ saveNewUser(): MyBatis-Plus save() → INSERT INTO sys_user
  │            │   │
  │            │   └─ 此时 MyMetaObjectHandler 自动填充审计字段:
  │            │        ├─ create_by = "system"
  │            │        │   来源: SecurityUtils.getCurrentUsernameOrSystem()
  │            │        │   此时无认证用户 → 返回默认值 "system"
  │            │        │
  │            │        ├─ update_by = "system"（同上）
  │            │        │
  │            │        ├─ create_time = LocalDateTime.now()
  │            │        └─ update_time = LocalDateTime.now()
  │            │
  │            └─ 返回 userId（MySQL AUTO_INCREMENT 自动生成）
  │
  └─[步骤2]─► SysUserRoleServiceImpl.assignDefaultRole(userId)
               │
               └─ SysUserMapper.insertUserRole(userId, 2)
                  → SQL: INSERT IGNORE INTO sys_user_role (user_id, role_id) VALUES (?, 2)
                  常量: Constants.DEFAULT_ROLE_ID = 2L（系统预设的"普通角色"）

返回: R.ok() → {"code": 200, "msg": "操作成功", "data": null}
```

### 2.3 涉及的数据表

| 表名              | 操作               | 写入数据说明                                                     |
| --------------- | ---------------- | ---------------------------------------------------------- |
| `sys_user`      | INSERT 一条记录      | user\_id 自增；密码 BCrypt 哈希；create\_by="system"；del\_flag="0" |
| `sys_user_role` | INSERT IGNORE 一条 | user\_id=新用户ID, role\_id=2（默认普通角色）                         |

### 2.4 返回值

- **成功**: `{"code": 200, "msg": "操作成功", "data": null}`
- **失败**: 由全局异常处理器 `GlobalExceptionHandler` 统一捕获，返回 `{"code": 400/500, "msg": "具体错误原因", "data": null}`

## 三、接口二：用户登录 `POST /auth/login`

### 3.1 请求数据

| 字段         | 来源                                   | 说明               |
| ---------- | ------------------------------------ | ---------------- |
| `username` | 用户输入                                 | 登录账号             |
| `password` | 用户输入                                 | 明文密码             |
| 客户端 IP     | `HttpServletRequest.getRemoteAddr()` | 由 Servlet 容器自动获取 |

### 3.2 数据链路

```
LoginReq (JSON Body) + HttpServletRequest
  │
  ▼
AuthController.login()
  │  日志：[登录] 收到登录请求
  │
  ▼
AuthServiceImpl.login(LoginReq, requestIp)
  │
  ├─[步骤1]─► SysUserServiceImpl.getUserEntityByUserName(username)
  │            SysUserMapper.selectUserByUserName()
  │            → SQL: SELECT * FROM sys_user WHERE user_name=? AND del_flag='0'
  │            返回完整的 SysUser 实体（含 BCrypt 密码哈希、status、userId 等所有字段）
  │            若查不到 → 抛 401 "用户不存在或密码错误"
  │
  ├─[步骤2]─► LoginService.login(username, password, userId, hashedPwd, status)
  │            │
  │            ├─ 校验用户状态: status == "1"（停用） → 抛 401 "用户已被停用"
  │            │
  │            ├─ BCrypt 密码比对: passwordEncoder.matches(明文, 哈希)
  │            │   不匹配 → 抛 401 "密码错误"
  │            │
  │            └─ TokenService.createToken(userId, username)
  │                 │
  │                 ├─ 构建 JWT Payload:
  │                 │   ┌──────────┬─────────────────────┐
  │                 │   │ 字段     │ 值                  │
  │                 │   ├──────────┼─────────────────────┤
  │                 │   │ userId   │ 如 "1"              │
  │                 │   │ username │ 如 "admin"          │
  │                 │   │ iat      │ 签发时间（当前时间） │
  │                 │   │ exp      │ iat + 86400000ms    │
  │                 │   └──────────┴─────────────────────┘
  │                 │
  │                 ├─ JwtTokenProvider.createToken(claims):
  │                 │   用 HMAC-SHA256 签名生成 JWT 字符串
  │                 │   签名密钥: jwt.secret
  │                 │     (application-dev.yml: "DevSecretKeyForJWTTokenGenerationMustBeLongEnough123456")
  │                 │   过期时间: jwt.expiration
  │                 │     (application.yml: 86400000 毫秒 = 24 小时)
  │                 │
  │                 └─ 存入 Redis:
  │                     Key:   login_tokens:1（"login_tokens:" + userId）
  │                     Value: JWT 字符串
  │                     TTL:   86400000 毫秒（与 JWT 一致）
  │
  ├─[步骤3]─► AuthResponseBuilder.buildLoginResp(user, token, requestIp)
  │            │
  │            ├─ MapStruct (AuthConvert.toLoginResp):
  │            │   SysUser 实体 → LoginResp 基础字段
  │            │   字段对应: userId, userName, nickName
  │            │   （roles 和 permissions 暂时忽略，后续手动填充）
  │            │
  │            ├─ 设置登录元信息:
  │            │   ├─ token     = JWT 字符串
  │            │   ├─ loginTime = LocalDateTime.now()
  │            │   ├─ expireTime = loginTime + jwt.expiration (86400000ms)
  │            │   ├─ ip        = request.getRemoteAddr()
  │            │   └─ address   = request.getRemoteAddr()
  │            │
  │            ├─ 查询角色标识列表 (roles):
  │            │   SysRoleMapper.selectRoleKeysByUserId(userId)
  │            │   → SQL:
  │            │      SELECT r.role_key
  │            │      FROM sys_role r
  │            │      INNER JOIN sys_user_role ur ON r.role_id = ur.role_id
  │            │      WHERE ur.user_id = ? AND r.status='0' AND r.del_flag='0'
  │            │   例如 admin 返回: ["admin"]
  │            │
  │            └─ 查询权限标识列表 (permissions):
  │                SysMenuMapper.selectMenuPermsByUserId(userId)
  │                → SQL:
  │                   SELECT DISTINCT m.perms
  │                   FROM sys_menu m
  │                   INNER JOIN sys_role_menu rm ON m.menu_id = rm.menu_id
  │                   INNER JOIN sys_role r ON rm.role_id = r.role_id
  │                   INNER JOIN sys_user_role ur ON rm.role_id = ur.role_id
  │                   WHERE ur.user_id = ?
  │                     AND r.status='0' AND r.del_flag='0'
  │                     AND m.status='0'
  │                     AND m.perms IS NOT NULL AND m.perms != ''
  │                SQL 走 4 表关联: sys_user → sys_user_role → sys_role_menu → sys_menu
  │                例如 admin 返回: ["system:user:list", "system:user:add", ...]
  │
  ├─[步骤4]─► 更新登录记录:
  │            SysUserMapper.updateUserLoginInfo(userId, loginIp, now)
  │            → SQL: UPDATE sys_user SET login_ip=?, login_date=? WHERE user_id=?
  │
  └─ 返回: R.ok(LoginResp)

最终返回的 LoginResp 完整结构:
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "userId": 1,           // 来自 sys_user.user_id
    "userName": "admin",   // 来自 sys_user.user_name
    "nickName": "若依管理员", // 来自 sys_user.nick_name
    "token": "eyJhbG...",  // JWT 字符串，有效期 24h
    "loginTime": "2026-06-15 19:30:00",   // 服务器当前时间
    "expireTime": "2026-06-16 19:30:00",  // loginTime + 24h
    "ip": "127.0.0.1",     // request.getRemoteAddr()
    "address": "127.0.0.1",// 同 IP，暂未解析地理位置
    "roles": ["admin"],    // sys_role 表中该角色的 role_key
    "permissions": [       // sys_menu 表中被授权的 perms 字段
      "system:user:list",
      "system:user:add",
      ...
    ]
  }
}
```

### 3.3 涉及的数据表

| 表名              | 操作              | 用途                        |
| --------------- | --------------- | ------------------------- |
| `sys_user`      | SELECT + UPDATE | 查询用户信息（含密码哈希）+ 更新登录 IP/时间 |
| `sys_role`      | SELECT（JOIN）    | 获取用户角色标识 role\_key        |
| `sys_user_role` | 隐式（JOIN）        | 用户-角色多对多中间表               |
| `sys_menu`      | SELECT（JOIN）    | 获取用户权限标识 perms            |
| `sys_role_menu` | 隐式（JOIN）        | 角色-菜单多对多中间表               |

### 3.4 涉及的外部存储

| 组件    | Key/配置                  | 操作      | 用途                                |
| ----- | ----------------------- | ------- | --------------------------------- |
| Redis | `login_tokens:{userId}` | SET（写入） | 缓存 JWT Token，实现单点登录（新登录覆盖旧 Token） |
| 配置    | `jwt.secret`            | 读取      | JWT HMAC-SHA256 签名密钥              |
| 配置    | `jwt.expiration`        | 读取      | Token 有效期（86400000ms）             |

## 四、接口三：获取当前用户信息 `GET /auth/info`

### 4.1 请求数据

本接口不接收 Body，仅依赖 HTTP 请求头中的 JWT Token。

### 4.2 前置拦截：JwtAuthenticationFilter

在 Controller 方法执行之前，Spring Security 的过滤器链会先执行 `JwtAuthenticationFilter`：

```
HTTP 请求到达
  │
  ▼
JwtAuthenticationFilter.doFilterInternal()
  │
  ├─[1]─► 从请求头提取 Token:
  │       ruoyiProperties.security.tokenHeader = "Authorization" (application.yml)
  │       ruoyiProperties.security.tokenPrefix = "Bearer "     (application.yml)
  │       截取 "Bearer " 之后的 JWT 字符串
  │
  ├─[2]─► TokenService.validateToken(token): 双重验证
  │        ├─ JWT 验证:
  │        │   JwtTokenProvider.validateToken()
  │        │   检查 HMAC-SHA256 签名是否正确
  │        │   检查 exp（过期时间）是否已超过当前时间
  │        │   签名无效或已过期 → 返回 false，过滤器放行（后续返回 401/403）
  │        │
  │        └─ Redis 验证:
  │            从 JWT Payload 中解析出 userId
  │            Redis 查询: GET login_tokens:{userId}
  │            比较 Redis 中的 Token 与请求的 Token 是否一致
  │            不一致（== null 或 !=） → 已被登出或新登录覆盖，返回 false
  │
  ├─[3]─► Token 验证通过后，构建 Spring Security 认证上下文:
  │        ├─ 从 JWT Payload 解析 userId
  │        ├─ 从 JWT Payload 解析 username
  │        │
  │        ├─ 查询权限 → 构建 authorities:
  │        │   PermissionService.getPermsByUserId(userId)
  │        │   → 每个权限字符串作为一个 SimpleGrantedAuthority("system:user:list")
  │        │
  │        ├─ 查询角色 → 追加 authorities:
  │        │   PermissionService.getRoleKeysByUserId(userId)
  │        │   → 每个角色 key 加上 ROLE_ 前缀作为一个 SimpleGrantedAuthority("ROLE_admin")
  │        │
  │        └─ 构建 UsernamePasswordAuthenticationToken:
  │            ├─ principal = userId（字符串）
  │            ├─ credentials = null
  │            ├─ authorities = [权限列表 + ROLE_角色列表]
  │            └─ details = username（字符串）
  │            存入 SecurityContextHolder.getContext()
  │
  └─[4]─► filterChain.doFilter() 放行到后续过滤器 → 到达 AuthController
```

### 4.3 数据链路（Controller 之后）

```
AuthController.getInfo()
  │
  ▼
AuthServiceImpl.getAuthInfo()
  │
  ├─[1]─► SecurityUtils.getRequiredCurrentUserId()
  │       从 SecurityContextHolder 读取 Authentication 对象
  │       authentication.getPrincipal() → 拿到 userId（字符串）
  │       解析为 Long
  │       若上下文无认证信息 → 直接抛异常 → 返回 401
  │
  ├─[2]─► SysUserServiceImpl.getUserEntityById(userId)
  │       MyBatis-Plus getById(userId)
  │       → SELECT * FROM sys_user WHERE user_id=?
  │       查不到 → 抛 401 "用户不存在"
  │
  ├─[3]─► AuthResponseBuilder.buildAuthInfoResp(user)
  │        │
  │        ├─ SysUserConvert.toResp(user):
  │        │   MapStruct 将 SysUser 实体 → SysUserResp
  │        │   字段: userId, deptId, userName, nickName, email,
  │        │         phonenumber, sex, avatar, status, remark, createTime
  │        │   注意: password 字段被 @JsonIgnore 标记，不会出现在 JSON 中
  │        │         roles 字段（List）为空数组
  │        │
  │        ├─ 查询角色:
  │        │   SysRoleMapper.selectRoleKeysByUserId(userId)
  │        │   → 同登录流程的 roles 查询
  │        │
  │        └─ 查询权限:
  │            SysMenuMapper.selectMenuPermsByUserId(userId)
  │            → 同登录流程的 perms 查询
  │
  └─ 返回: R.ok(AuthInfoResp)

最终返回的 AuthInfoResp 完整结构:
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "user": {
      "userId": 1,                  // sys_user.user_id
      "deptId": 103,                // sys_user.dept_id
      "userName": "admin",          // sys_user.user_name
      "nickName": "若依管理员",      // sys_user.nick_name
      "email": "ry@163.com",        // sys_user.email
      "phonenumber": "15888888888", // sys_user.phonenumber
      "sex": "1",                   // sys_user.sex
      "avatar": "",                 // sys_user.avatar
      "status": "0",                // sys_user.status
      "remark": null,               // sys_user.remark (继承自 BaseEntity)
      "createTime": "2026-06-01 10:00:00",  // sys_user.create_time
      "roles": []                   // 非数据库字段，此处为空数组
    },
    "roles": ["admin"],             // sys_role.role_key，通过 sys_user_role 关联
    "permissions": [                // sys_menu.perms，通过 4 表 JOIN 查询
      "system:user:list",
      ...
    ]
  }
}
```

### 4.4 涉及的数据表

| 表名              | 操作           | 用途       |
| --------------- | ------------ | -------- |
| `sys_user`      | SELECT       | 获取用户完整信息 |
| `sys_role`      | SELECT（JOIN） | 获取角色标识   |
| `sys_user_role` | 隐式（JOIN）     | 用户-角色关联  |
| `sys_menu`      | SELECT（JOIN） | 获取权限标识   |
| `sys_role_menu` | 隐式（JOIN）     | 角色-菜单关联  |

### 4.5 涉及的外部存储和组件

| 组件                    | Key                     | 操作  | 用途                       |
| --------------------- | ----------------------- | --- | ------------------------ |
| Redis                 | `login_tokens:{userId}` | GET | 验证 Token 是否有效（未被登出/覆盖）   |
| SecurityContextHolder | —                       | 读取  | 从 JWT 过滤器设置的上下文中拿 userId |
| JWT Payload           | —                       | 解析  | 提取 userId 和 username     |

## 五、接口四：用户登出 `POST /auth/logout`

### 5.1 请求数据

不接收 Body，仅依赖 HTTP 请求头。

### 5.2 数据链路

```
AuthController.logout(HttpServletRequest)
  │
  ├─ 读取请求头:
  │   ruoyiProperties.security.tokenHeader → "Authorization" (application.yml)
  │   ruoyiProperties.security.tokenPrefix → "Bearer "     (application.yml)
  │   截取 JWT 字符串
  │   若请求头为空 → 直接返回成功（幂等）
  │
  ▼
AuthServiceImpl.logout(authorizationHeader)
  │
  ├─ 校验: 请求头为空？ → 直接返回
  ├─ 校验: 不以 "Bearer " 开头？ → 直接返回
  │
  ├─ 截取 Token（去掉 "Bearer " 前缀）
  │
  ├─ TokenService.getUserIdFromToken(token)
  │   JwtTokenProvider.getUserId(token)
  │   → 解析 JWT Payload，取出 userId 字段
  │   → 注意: 此处不需要 Redis 验证，仅解析 JWT 即可
  │
  └─ LoginService.logout(userId)
       TokenService.removeToken(userId)
       → Redis: DEL login_tokens:{userId}
       → 删除后，后续任何使用该 Token 的请求都会在 JwtAuthenticationFilter
         的 validateToken() 中因 Redis 缓存不存在而失败 → 返回 401

返回: R.ok() → {"code": 200, "msg": "操作成功", "data": null}
```

### 5.3 登出后的 Token 失效机制

```
用户携带已登出的 Token 再次请求 /auth/info
  │
  ▼
JwtAuthenticationFilter.validateToken(token)
  ├─ JWT 签名验证: 通过 ✓（JWT 自身尚未过期）
  ├─ 解析 userId
  └─ Redis GET login_tokens:{userId} → null（已被登出删除）
     → token.equals(null) = false
     → validateToken() 返回 false
     → 不设置 SecurityContext
     → 后续 /auth/info 方法中 SecurityUtils.getRequiredCurrentUserId()
       检测到无认证上下文 → 直接抛 AuthenticationCredentialsNotFoundException
       → 返回 401
```

### 5.4 涉及的外部存储

| 组件          | Key                           | 操作      | 用途                          |
| ----------- | ----------------------------- | ------- | --------------------------- |
| Redis       | `login_tokens:{userId}`       | DEL（删除） | 删除缓存的 Token，使其立即失效          |
| JWT Payload | —                             | 解析（不验证） | 提取 userId 用于定位 Redis Key    |
| 配置          | `ruoyi.security.token-header` | 读取      | 确定从哪个请求头取值（"Authorization"） |
| 配置          | `ruoyi.security.token-prefix` | 读取      | 确定 Token 前缀（"Bearer "）      |

## 六、四个接口涉及的全量数据总览

### 6.1 数据库表

| 表名              |   注册   |        登录       |     获取信息     |  登出 |
| --------------- | :----: | :-------------: | :----------: | :-: |
| `sys_user`      | INSERT | SELECT + UPDATE |    SELECT    |  —  |
| `sys_user_role` | INSERT |   SELECT（JOIN）  | SELECT（JOIN） |  —  |
| `sys_role`      |    —   |   SELECT（JOIN）  | SELECT（JOIN） |  —  |
| `sys_menu`      |    —   |   SELECT（JOIN）  | SELECT（JOIN） |  —  |
| `sys_role_menu` |    —   |   SELECT（JOIN）  | SELECT（JOIN） |  —  |

### 6.2 Redis 操作

| 接口   | Redis Key               | 操作         | 时机                           |
| ---- | ----------------------- | ---------- | ---------------------------- |
| 登录   | `login_tokens:{userId}` | SET（写入或覆盖） | 认证成功后                        |
| 获取信息 | `login_tokens:{userId}` | GET（校验）    | 每次请求，JwtAuthenticationFilter |
| 登出   | `login_tokens:{userId}` | DEL（删除）    | 登出时                          |

### 6.3 配置项

| 配置项                           | 来源文件                  | 取值                                                        | 使用位置                 |

## 七、Token 认证全生命周期

```
用户注册
  │  sys_user 写入用户记录
  │  sys_user_role 分配默认角色
  ▼
用户登录
  │  LoginService 校验密码
  │  TokenService.createToken() → JWT 签名 + Redis 缓存
  │  返回 Token 给前端
  ▼
前端携带 Token 访问受保护接口
  │  JwtAuthenticationFilter 拦截
  │  ├─ 解析 JWT 签名
  │  ├─ Redis 对比（Token 是否被登出/覆盖）
  │  └─ 设置 SecurityContext（userId + username + authorities）
  ▼
Controller / Service 执行
  │  SecurityUtils.getCurrentUserId() 从上下文读取
  │  MyMetaObjectHandler 从 SecurityUtils 拿 username 填充审计字段
  ▼
用户登出
  │  Redis DEL login_tokens:{userId}
  │  Token 立即失效（即使 JWT 尚未过期，Redis 缓存缺失也会拒绝）
  ▼
后续请求
  │  JwtAuthenticationFilter → Redis 无缓存 → validateToken() 失败
  │  → SecurityContext 为空 → 返回 401
```
